        # sqlite — Транзакции и блокировки

        Homework-шаблон для урока **l1_transactions_and_locking** (Транзакции и блокировки) на платформе Vibe Learn.

        ## Что делать

        На Go с modernc.org/sqlite реализуй банковский перевод Transfer(db, fromID, toID, amount)
как атомарную транзакцию: открой её через `BEGIN IMMEDIATE` (RESERVED сразу), сделай два
UPDATE через арифметику в SQL (`balance = balance ± amount`), проверь, что баланс не уходит
в минус (иначе ROLLBACK с ошибкой). Тесты гоняют на :memory:-базе: проверяют, что (1) сумма
балансов сохраняется после серии переводов, (2) перевод при недостатке средств откатывается
целиком, (3) запусти N параллельных goroutine-переводов и убедись, что итоговая сумма
балансов инвариантна (атомарность держится). Добавь обработку SQLITE_BUSY (логируй, ретрай).

## Контекст (из transfer-задачи урока)

Бэкенд на Python (sqlite3, режим по умолчанию — rollback journal). В логах периодически
всплывает `sqlite3.OperationalError: database is locked`, но только под нагрузкой. Код
перевода денег выглядит так: открывают соединение, делают `SELECT balance` (читают баланс),
что-то считают в Python, потом `UPDATE` баланса, потом `commit()`. Никаких явных BEGIN нет
— полагаются на дефолтное поведение драйвера. Две параллельные операции перевода стабильно
воспроизводят ошибку.

**Вопрос:** объясни:
(a) почему именно эта схема (SELECT → счёт в коде → UPDATE без явного BEGIN IMMEDIATE)
    приводит к deadlock-у на апгрейде и SQLITE_BUSY;
(b) при чём тут лестница SHARED → RESERVED и тип транзакции DEFERRED;
(c) как переписать, чтобы убрать гонку (тип BEGIN, длина транзакции);
(d) почему «просто добавить retry на SQLITE_BUSY» — это лечение симптома, а не причины,
    и в чём опасность считать баланс в коде между SELECT и UPDATE.

## Recap из урока

- SQLite **полностью ACID**, но блокировки — на уровне **всего файла БД**, не строк. Нет MVCC и нет версий строк (в отличие от PostgreSQL).
- Лестница блокировок: **UNLOCKED → SHARED (читатели) → RESERVED (намерение писать) → PENDING → EXCLUSIVE (запись)**. Писатель строго один.
- **DEFERRED** (по умолчанию) берёт блокировку лениво → риск deadlock на апгрейде SHARED→RESERVED. **IMMEDIATE** берёт RESERVED сразу — правильный выбор для пишущих транзакций.
- Атомарность даёт **rollback journal**: оригиналы страниц копируются в `-journal`, при крэше накатываются обратно. Файл никогда не в полу-записанном виде.
- Автокоммит = отдельный fsync на каждую запись. Оборачивай пачку записей в один `BEGIN ... COMMIT` — ускорение на порядки.

        - Go 1.22+
        - SQLite встроена — **никакого сервера и docker-compose**. БД это один файл (`DATABASE_PATH`) или `:memory:` в тестах. Драйвер `modernc.org/sqlite` — чистый Go, без CGO, так что CI собирается без компилятора C.
